## 构建

在仓库根目录执行（仅需 Node.js，无 npm 依赖）：

```sh
node scripts/build-wechat.cjs
```

输出 `dist/wechat-minigame/`，包含 `game.js`、`game.json`、`project.config.json`、原生运行层 `runtime.js`、`native-audio.js`、从共享游戏源码生成的 `core.js` 和 `assets/audio/` 下的本地 WAV 音效。不要手动编辑生成文件。

已确认小游戏 AppID 后重新构建：

```sh
node scripts/build-wechat.cjs --appid 你的真实小游戏AppID
```

AppID 缺省时配置保持为空，不冒用示例项目的 AppID。AppSecret 和上传密钥不参与代码构建，也不要放进源码或版本库。开发者工具个人配置和构建目录已加入忽略列表。

## 导入与发布

1. 先在微信公众平台确认账号类型为「小游戏」，取得该账号的 AppID。用户尚未确认账号时，不要把普通公众号或其他人的 AppID 当作小游戏账号使用。
2. 在微信开发者工具中导入生成的 `dist/wechat-minigame/`（有 game.json 的目录），填写自己的 AppID，使用当前稳定基础库编译。保留合法域名检查。
3. 用工具生成真机预览，在 iOS 和 Android 微信中验证启动、双指移动+攻击、跳跃、五层关卡、音效开关、持续移动节奏、切后台/来电中断/恢复和刘海屏按钮。
4. 真机通过后上传开发版本。账号资料、名称图标、简介、类目及平台显示的资质/备案等事项，应根据该主体的后台提示完成；本代码包不代表账号已经具备发布资格。
5. 在后台确认上传版本，按实际页面提交审核。审核通过后执行发布，再核验微信内的正式入口。上传成功、审核通过和正式发布是不同状态，要分别核实。

本次浏览器的站点安全策略阻止了自动访问微信公众平台，因此没有读取或改变任何后台账号资料，也没有提交审核。账号持有人需自行登录确认账号；扫码、主体信息和平台协议应由本人核实处理。

## 已完成的适配

- 使用 wx.createCanvas 的首个 Canvas 作为主画布，其余画布绘制复用的游戏画面，保持人物比例及高 DPI 清晰度。
- 圆角使用基础 Canvas 路径绘制，避开开发者工具对 roundRect 半径参数的兼容差异，兼容缺少该方法的运行环境。
- 触屏按钮使用单层圆角渐变，按下通过颜色变化反馈，避免双层底板的堆叠观感。按钮在 Canvas 内绘制，通过 wx.onTouchStart/Move/End/Cancel 处理，多根手指分别持有动作；支持同时移动与连击、方向滑动、取消触摸与抬手开始/暂停。
- 小游戏采用 wx.createInnerAudioContext 的原生播放器（useWebAudioImplement:false），通过 wx.setInnerAudioOption 设置 obeyMuteSwitch:false，处理 iPhone 上上下文已运行但静音开关仍抑制声音的问题。网页版本保留 Web Audio。
- 开场、战斗、拾取、脚步、跳跃及持续移动音效由共享音效定义在构建时生成本地 PCM WAV，不下载外部资源。8 个短音效播放器加 1 个移动循环播放器，移动音量平滑变化；静音偏好通过 wx 本地存储保存。切后台、中断或销毁时停止播放；原生播放失败显示“重试声音”。
- wx.getPerformance 的微秒时间转换为游戏使用的毫秒，避免游戏速度错误。
- 根据安全区和右上角胶囊位置放置画面；切后台停止循环与输入，返回保持暂停，由玩家主动继续。
- 补给为每局 3 次免费领取。本版本未接入广告 SDK，不显示“看广告”承诺，也不接支付或分享奖励。
- 游戏本身不调用联网、微信登录、昵称头像、位置、通讯录等接口；只在设备本地保存音效静音偏好。后续接入其他能力时，应同步更新相关说明。
